# 레퍼런스 분석 — 스킬 라이브러리

> P1 · researcher 작성.
> 규칙: `### RP-<번호>` 제목 1개 = 반영 포인트 1개. 최소 3개.
> 각 반영 포인트에 `출처: R<번호>` 필수 (references.md 에 있는 번호).

## 공통 패턴

- **상단 압축 구조**: 큰 제목 + 검색(아이콘 또는 검색 바) → 유형/카테고리 pill 칩 가로 스크롤 → 정렬·보기 전환 → 목록 순서가 반복됨 (R1, R2, R3, R6).
- **흑백 상태 표현 칩**: 선택 칩은 검정 채움(또는 검정 테두리), 비선택은 흰 바탕/연회색 채움으로 구분. 일부는 칩에 개수를 붙임 (R2, R3).
- **그림자 없는 카드**: 연회색 채움 또는 1px 테두리만으로 카드를 구분하고, 카드 하단/우상단에 메타 정보(다운로드 수, 난이도, 기간)를 작게 배치 (R6, R9).
- **프롬프트 복사 블록**: 번호 단계 + 회색 박스 안 프롬프트 미리보기 + 박스 내 복사 버튼. 사용 도구별로 프롬프트를 전환하는 사례도 있음 (R4, R5).
- **권한 표시 2단계**: 목록/섹션에서는 작은 "멤버십 전용" 배지로 먼저 알리고, 상세에서는 앞부분 미리보기 + 자물쇠 + 잠금 사유 한 줄 (R7, R8).
- **다운로드는 파일 형식을 라벨에 명시**: "PDF로 다운로드"처럼 형식을 밝힌 아이콘 + 라벨 (R10).
- 관련 미션 연결을 직접 보여 주는 레퍼런스는 이번 검색에서 찾지 못함 — P2에서 카드 하단 링크 행 등으로 직접 설계 필요.

## 반영 포인트

### RP-1. 상단에 "제목 + 검색 바 + 카테고리 태그 칩(가로 스크롤)" 고정 구조

- 출처: R1, R2, R3
- 이유: prd.md §6-3 필수 기능(카드 목록·검색·태그 필터)과 US-2의 "한곳에서 찾아"를 한 화면 상단에서 해결. 검색어 입력 중에도 칩 필터가 유지되는 R3 방식이면 검색과 태그 필터를 동시에 걸 수 있음.
- 반영 방식: 390px 화면 상단에 heading-1 "스킬 라이브러리" → `{colors.field}` 채움 pill 검색 바(돋보기 + 지우기 X) → "전체 / 기획 / 디자인 / 개발 / 자동화 …" pill 칩 가로 스크롤. design.md에 맞게 흑백으로 — 선택 칩은 `{colors.ink}` 채움 + 흰 글씨, 비선택은 `{colors.canvas-soft}` 채움 + ink 글씨(R6의 보라, R3의 색상 강조는 쓰지 않음). R2처럼 칩 라벨에 개수("전체 24")를 붙이는 방식은 선택 사항으로 P2에 넘김.

### RP-2. 스킬 카드 목록은 그림자 없는 카드 + 우상단 메타 배지(난이도·권한)

- 출처: R6, R8, R9
- 이유: prd.md §6-3 카드 필드(스킬명·카테고리·난이도·사용 도구·업데이트 날짜·권한) 중 목록에서 판단에 필요한 것만 추려 보여야 함. R9처럼 난이도를 배지로 제목과 분리하면 "난이도 표시" 필수 기능을 한눈에 충족하고, R8처럼 권한 배지를 먼저 보여 주면 무료/유료/코호트 전용 여부를 열기 전에 알 수 있음.
- 반영 방식: 카드 = `{colors.canvas}` 바탕 + 1px `{colors.hairline-soft}` 테두리, `{rounded.md}`, 그림자 없음. 카드 안 상단: 카테고리(caption, muted) / 우상단 pill 배지 "입문·중급·고급" + 권한 배지("무료"·"멤버십"·"3기 전용"). 가운데 스킬명(title 600), 한 줄 "언제 쓰나요" 요약(body-sm, muted). 하단: 사용 도구 태그 pill + 업데이트 날짜(caption). design.md에 맞게 흑백으로 — R9의 파랑 배지는 쓰지 않고 `{colors.canvas-soft}` 채움 pill + label 12px/600으로 통일.

### RP-3. 카드 상세에 "번호 단계 + 프롬프트 박스 + 박스 내 복사 pill 버튼"

- 출처: R4, R5
- 이유: 카드 필드 "프롬프트 또는 파일", "사용 순서"와 필수 기능 "복사 버튼"을 한 블록에서 해결. 긴 프롬프트를 페이드로 잘라 미리보기하면 390×844 화면에서도 스크롤 부담이 적고, 복사까지의 동선이 한 번의 탭으로 짧아짐(US-2 "복사하거나").
- 반영 방식: "사용 순서" 섹션에 원형 숫자(ink 채움, 흰 숫자) 단계 리스트. 프롬프트는 `{colors.canvas-soft}` 채움 `{rounded.sm}` 박스에 4~5줄 미리보기 + 하단 페이드 + "전체 보기" 텍스트 링크, 박스 우하단에 흰 바탕 + `{colors.hairline}` 테두리 pill "복사" 버튼(아이콘 + 라벨). 복사 후 "복사했어요" 토스트. R5의 주황 전폭 CTA는 design.md에 맞게 흑백으로 — 주요 CTA가 필요하면 `{colors.ink}` 채움 pill로. R5의 사용 도구 세그먼트(ChatGPT/Claude/Gemini 전환)는 도구별 프롬프트가 여러 개인 카드에만 선택적으로 적용하도록 P2에 넘김.

### RP-4. 권한 없는 카드는 목록에서 배지로 알리고, 상세에서 앞부분 미리보기 + 자물쇠 + 사유 한 줄

- 출처: R7, R8
- 이유: prd.md §6-3 권한 필드(무료/유료/특정 코호트 전용)를 사용자가 헷갈리지 않게 해야 함. 잠긴 카드도 "언제 쓰나요·예시 결과" 앞부분은 보여 주면 무엇이 잠겼는지 알 수 있고, 코호트 전용처럼 결제로 풀 수 없는 잠금도 사유 문장으로 구분 가능.
- 반영 방식: 목록 카드에는 권한 배지 + 작은 자물쇠 아이콘(ink). 상세에서는 상단 메타·요약까지 공개하고 프롬프트/파일 블록 위치에 흐림 처리 + 자물쇠 + "멤버십 회원에게 열려 있어요" 또는 "3기 멤버 전용 스킬이에요" 한 줄. design.md에 맞게 흑백으로 — R7의 연보라 자물쇠·그라데이션 CTA, R8의 파랑 CTA는 쓰지 않음. 결제/구독 유도 CTA는 넣지 않음(아래 "반영하지 않는 것" 참고).

### RP-5. 파일 다운로드는 형식·용량을 밝힌 아이콘 + 라벨 pill

- 출처: R10, R6
- 이유: 필수 기능 "파일 다운로드"와 US-2 "내려받는다". 스킬 파일은 .md·.zip·.json 등 형식이 다양해 내려받기 전에 형식을 알려 주는 편이 실수를 줄임. R6처럼 카드 하단 메타 한 줄로 다운로드 규모를 보여 주는 방식도 활용 가능.
- 반영 방식: 상세의 "프롬프트/파일" 블록에서 파일 카드는 파일명 + "ZIP · 12KB"(caption, muted) + 우측 흰 바탕 외곽선 pill "↓ 다운로드". 목록 카드 하단에는 파일 포함 여부 아이콘만 표시. R10의 주황 텍스트는 design.md에 맞게 흑백으로(ink).

### RP-6. 예시 결과는 상세 안에서 접힌 섹션 → 탭하면 펼쳐 보기

- 출처: R4, R7
- 이유: 필수 기능 "예시 결과 보기". R4의 잘린 미리보기 + 펼치기, R7의 앞부분 미리보기 방식이 모두 "일부를 먼저 보여 주고 필요하면 더 본다"는 같은 원리. 카드 상세가 길어지는 것(준비물·사용 순서·주의할 점·예시 결과)을 막는 데 적합.
- 반영 방식: "예시 결과" 섹션을 `{colors.canvas-soft}` 박스 미리보기(텍스트 3줄 또는 이미지 썸네일 1장) + "예시 결과 전체 보기" 텍스트 버튼으로 두고, 탭 시 바텀시트(흰 바탕, 상단 `{rounded.md}`, 그림자 없음)로 전체 표시. 예시 결과 이미지 자체는 콘텐츠이므로 컬러 허용(design.md "콘텐츠가 색을 공급").

## 반영하지 않는 것

- R7 "프리미엄 멤버십 보러가기", R8 "멤버십 특가로 … 보기" 등 구독·결제 유도 CTA — MVP 범위 밖(구매·결제). 잠금 화면에는 사유 안내만 두고 결제 동선은 연결하지 않음.
- R6 "66번 다운로드 됐어요" 같은 인기·다운로드 수 랭킹 노출 — 허들링 픽(인기 자산 노출·선정)과 혼동될 수 있고 MVP 범위 밖. 스킬 라이브러리는 하이서가 만든 검증 스킬만 다루므로 업데이트 날짜만 표시.
- R2의 평점 드롭다운, R8의 별점·평가 카드 — 사용자 피드백/평가 기능은 MVP 범위 밖(피드백 제외).
- R3·R6의 작성자(사용자 프로필) 표시 — 멤버 제작 자산 판매(허들링 픽)·판매 수익 영역 패턴이므로 제외. 스킬 작성자는 하이서 단일이라 표시 불필요.
- R5 주황, R6 보라, R7 연보라·그라데이션, R8·R9 파랑 등 브랜드 색 강조 — design.md 위반(흑백 + accent 블루는 상업 신호 전용, CTA 사용 금지). 모두 흑백 톤으로 치환.
- R1의 어두운 배경(다크 테마) — design.md의 흰 캔버스 원칙과 충돌.
- R2·R3의 이미지 중심 2~3열 그리드 — 스킬 카드는 텍스트 정보(스킬명·언제 쓰나요·난이도)가 핵심이라 1열 카드 리스트가 적합. 그리드 보기 전환 토글도 MVP에서는 넣지 않음.
