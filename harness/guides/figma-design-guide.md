## 2. 이름 규칙 — 🚦 게이트 검사

| 대상         | 규칙                                                                 | 예                                   | 출처                    |
| ------------ | -------------------------------------------------------------------- | ------------------------------------ | ----------------------- |
| Figma 페이지 | `P3 · {주제} · 시안`, `P4 · {주제} · 시스템`, `P5 · {주제} · 플로우` | `P3 · 내 자산 등록 · 시안`           | 임의                    |
| 화면 프레임  | `{시안 문자} · {화면명}` (A~C)                                       | `B · 작업 데스크`                    | 템플릿                  |
| 레이어       | `{p}.` + 소문자 역할명, 점으로 계층, 0부터 번호                      | `b.learning.0.title`, `b.tab2.label` | 템플릿                  |
| 접두사 `{p}` | 시안 문자 소문자 (P4는 **선택된 시안 문자**)                         | 시안 B → `b.`                        | 템플릿 추정 → 임의 확정 |
| 버튼         | `.cta`(주요 행동) 또는 `.btn`으로 끝남                               | `b.cta`, `b.bell.btn`                | 임의                    |
| 탭           | `{p}.tab0` ~ `{p}.tab3`                                              | `b.tab1`                             | 템플릿                  |

- `Frame`, `Rectangle`, `Group` 같은 **기본 이름은 0건**이어야 합니다. (템플릿 원본에도 3곳이 남아 있습니다)
- 예외: 상태바 인스턴스는 원래 이름 그대로 둡니다.

## 4. 색상 — 🚦 게이트 검사 · [design.md]

- `rules.yaml` `design.colors` 12색만 씁니다. (흑백 + 파란색 1개)
- **파란색 `#0066ff`는 CTA에 쓰지 않습니다.** 커머스 신호(배지 등)에만 씁니다. (템플릿은 CTA와 활성 탭에 파란색 → 쓰지 않음)
- 상태(작성 중, 검수 대기, 마감 임박 등)는 **흑백 단계와 글자 굵기로만** 구분합니다. 템플릿의 초록·주황·빨강 상태색은 쓰지 않습니다.
- 값은 직접 넣지 말고 **Figma 변수에 연결**합니다. [템플릿의 semantic 토큰 방식]
- 색 변수는 **2단 구조**입니다: `Palette`(원본 hex, 선택 목록에서 숨김) → `Semantic`(역할 이름, Palette 참조). [Wanted Design Library 방식]
  - 노드의 색은 **`Semantic` 변수에만 연결**합니다. `Palette` 변수에 직접 연결하지 않습니다.
  - 새 색이 필요하면 먼저 `Palette`에 원본을 만들고, `Semantic` 변수가 그것을 참조하게 합니다. (새 hex는 `rules.yaml` 팔레트 승인이 먼저)

## 6. ★ 어기면 안 되는 것 (story-service.md) — 🚦 게이트 검사

- 더미 텍스트에 **이메일·전화번호·주민번호 형식, 실명, 실제 회사명·고객명, 기밀 표현**을 넣지 않습니다.
- 공개 범위 선택 UI가 있으면 **기본 선택은 `비공개`** 로 그립니다.
- 판매 신청 흐름을 그리면 **`검수 대기` 상태**를 거치게 그립니다.

1. `figma:figma-use` 스킬을 불러옵니다.
2. 페이지를 만들거나 엽니다. 기존 섹션이 있는 페이지의 (0,0)에 `createSection()`을 쓰지 않습니다.
3. 390×844 프레임 → 1장 골격 → 2장 이름 → 3~5장 스타일 순서로 그립니다.
4. 상태바는 `Status bar - iPhone 17 Pro` **인스턴스**를 넣습니다. 직접 그리지 않습니다.
5. `harness/scripts/figma-export.figma.js`로 노드 정보를 내보내고, 결과를 수정 없이 저장합니다.

## 9. 단계별 산출물 — P3 키스크린 → P4 시스템 → P5 유저 플로우

| 단계 | Figma 페이지           | 그리는 것                                                                                           | 🚦 게이트                                                                                             |
| ---- | ---------------------- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| P3   | `P3 · {주제} · 시안`   | 키스크린(화면 목록 S1) 시안 2~3개 `A/B/C · {S1 화면명}`                                             | 골격·이름·타이포·모서리·터치·CTA                                                                      |
| P4   | `P4 · {주제} · 시스템` | 화면 목록 **S1~Sn 전체**에 필요한 컴포넌트(세트)와 변수·텍스트 스타일                               | system.md의 컴포넌트가 모두 내보내짐 · 서체·색·간격·그림자·타이포·모서리 · **변수 미연결 0건** [임의] |
| P5   | `P5 · {주제} · 플로우` | 화면 목록 **S1~Sn 전체**를 `{선택 시안 문자} · {화면명}` 프레임으로, S1→Sn 가로 배치·간격 80 [임의] | **화면 목록 ↔ 프레임 1:1 커버리지** + 1~6장 전부                                                      |

- 화면 목록은 `p2-spec/screen-spec.md`의 `## 화면 목록` 표가 기준입니다. 프레임 이름의 화면명은 표와 **글자까지 같아야** 합니다.
- P4 컴포넌트 안의 SOLID 색·itemSpacing·padding·모서리는 **모두 변수에 연결**합니다. 텍스트는 `type/*` 텍스트 스타일에 연결합니다.
- P5 화면의 반복 요소는 P4 컴포넌트 **인스턴스**로 넣고, 인스턴스와 하위 레이어 이름도 `{p}.` 규칙을 지킵니다.
- 바텀시트·토스트처럼 겹쳐 뜨는 화면도 한 장의 390×844 프레임으로 그리고, 골격(상태바·header·tabs·home-indicator)은 유지합니다.
