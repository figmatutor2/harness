# 허들링 앱 PRD — AI 실무 학습 플랫폼과 멤버 자산 마켓

안녕하세요. 아래 PRD를 기준으로 **허들링의 흩어진 자산(huddling.ai, huddling.club, Discord, 강의자료, 프롬프트/스킬 파일)을 하나의 앱 경험으로 통합**해주세요.

이 제품은 단순한 자료실이나 커뮤니티 앱이 아닙니다. 최종 목표는 **AI를 배우고, 내 업무에 적용하고, 결과물을 자산화하고, 선택적으로 판매까지 이어지는 AI 실무 학습 플랫폼**입니다.

---

## 1. 배경

현재 허들링의 자산은 여러 곳에 흩어져 있습니다.

- `huddling.ai`: 외부 유입과 브랜드 신뢰를 위한 공개 콘텐츠
- `huddling.club`: 멤버십/커뮤니티 성격의 도메인 자산
- Discord: 실제 대화, 실험, 멤버 사례, 스킬, 프롬프트, 운영 노하우가 쌓이는 공간
- 강의/라이브/워크숍 자료: 수업 이후 다시 찾아보기 어렵거나 흩어져 있는 교육 자산
- Claude Code, Cursor, Codex, Figma, 자동화 프롬프트 등: 실무 적용 가능성이 높은 유료 자산 후보

문제는 자산이 늘어날수록 멤버와 운영자 모두에게 정보 접근성이 떨어진다는 점입니다.

무료로 공개해도 되는 학습자료, 유료 회원 전용 자료, 하이서가 만든 검증된 스킬/프롬프트, 멤버가 만든 판매 가능 자산이 서로 뒤섞여 있으면 사용자는 무엇부터 봐야 할지 모르고, 운영자는 어떤 자료가 실제 수익 자산인지 관리하기 어렵습니다.

따라서 허들링 앱은 다음 문제를 해결해야 합니다.

1. 무료 회원이 허들링의 학습 흐름을 부담 없이 경험할 수 있어야 합니다.
2. 유료 회원은 강의자료, 프롬프트, 스킬, 미션, 피드백을 한곳에서 확인할 수 있어야 합니다.
3. Discord에 쌓인 실전 노하우를 단순 복붙이 아니라 **AI 에이전트가 읽고 이어서 작업할 수 있는 구조화된 자산**으로 재가공해야 합니다.
4. 유료 회원이 매달 만든 산출물을 선택적으로 판매 신청할 수 있어야 합니다.
5. 허들링은 판매 자산을 검수·큐레이션하고 수수료를 받는 방식으로 플랫폼 수익성을 확보해야 합니다.

---

## 2. 제품 비전

허들링 앱은 **AI 시대의 실무 실험실**입니다.

사용자는 콘텐츠를 보고 끝나는 것이 아니라, 직접 실험하고, 업무에 적용하고, 결과물을 만들고, 그 결과물을 다시 자산화할 수 있어야 합니다.

한 문장으로 정의하면 다음과 같습니다.

> 허들링 앱은 AI 실무 학습자료, 스킬/프롬프트 라이브러리, 멤버 산출물, 유료 자산 마켓을 연결하는 학습·실험·자산화 플랫폼입니다.

---

## 3. 핵심 유저스토리

### 3-1. 무료 학습자로서

**무료 학습자로서**, 허들링의 AI/Figma/자동화/바이브코딩 관련 콘텐츠를 부담 없이 둘러보고 싶다. 아직 유료 회원이 되기 전이므로 전체 자료를 다 보지는 못하더라도, 어떤 방식으로 배우고 실험하는 곳인지 명확히 알고 싶다.

### 3-2. 유료 멤버로서

**유료 멤버로서**, 강의자료, 다시보기, 템플릿, 프롬프트, 스킬 파일, 미션, 피드백을 한곳에서 확인하고 싶다. Discord에 흘러간 자료를 다시 찾느라 시간을 쓰고 싶지 않다.

### 3-3. 실험하는 멤버로서

**AI 실무 실험을 하는 멤버로서**, 매달 내가 만든 프롬프트, 스킬 파일, 자동화 템플릿, 업무 적용 사례를 제출하고 기록하고 싶다. 내 산출물이 단순 과제가 아니라 포트폴리오가 되면 좋겠다.

### 3-4. 판매를 원하는 멤버로서

**판매를 원하는 멤버로서**, 내가 만든 자료 중 일부를 선택해 판매 신청하고 싶다. 가격, 설명, 포함 파일, 사용 조건, 미리보기, 판매 상태, 수익 내역을 확인할 수 있어야 한다.

### 3-5. 구매자로서 (이번 범위 제외 · Phase 2)

**실무 자산을 구매하는 사용자로서**, 이 자료가 내 업무에 바로 쓸 수 있는지 알고 싶다. 단순 프롬프트 한 줄이 아니라 사용법, 예시, 필요한 도구, 난이도, 결과물이 명확해야 한다.

### 3-6. 허들링 클럽 운영자로서

**운영자로서**, 무료/유료/판매용 자료를 구분해서 관리하고 싶다. 멤버가 올린 자료를 검수하고, 좋은 자료를 ‘허들링 픽’으로 선정하고, 판매 수익과 정산 상태를 확인할 수 있어야 한다. 단, 모든 피드백과 검수를 하이서가 직접 떠안는 구조는 피하고 싶다.

---

## 4. 사용자들의 상황

- 사용자는 AI 도구를 배우고 싶지만, 무엇부터 실무에 적용해야 할지 모르는 경우가 많습니다.
- Discord 안에는 좋은 대화와 실전 팁이 쌓이지만, 나중에 다시 찾기 어렵습니다.
- 유료 멤버는 자료 접근권뿐 아니라 실행 리듬, 미션, 피드백, 사례를 기대합니다.
- 멤버가 만든 산출물은 품질 차이가 큽니다. 따라서 바로 오픈마켓으로 열면 신뢰가 무너질 수 있습니다.
- 하이서는 강의자이자 큐레이터이자 플랫폼 운영자입니다. 모든 콘텐츠를 직접 생산하는 구조는 장기적으로 지속 가능하지 않습니다.
- 초기 앱은 기능을 많이 넣기보다, 자료 접근·학습 흐름·자산 제출·검수 대기까지의 핵심 루프를 먼저 만들어야 합니다.
- 채팅과 실시간 커뮤니티 분위기는 Discord가 계속 담당합니다. 앱은 자료, 학습, 제출, 피드백, 자산화를 담당합니다.

## 5. 핵심 정보 구조

앱은 최소한 아래 섹션을 가져야 합니다.

```txt
[무료 학습자료]
누구나 볼 수 있는 콘텐츠

[유료 멤버 자료실]
강의자료, 템플릿, 프롬프트, 다시보기

[스킬 라이브러리]
하이서가 만든 검증된 스킬/프롬프트

[허들링 픽] (MVP 제외 · Phase 2)
멤버들이 만든 판매용 실무 자산

[내 학습]
미션, 제출물
(피드백: MVP 제외 · 구매한 자산: Phase 2)

[내 자산]
내가 만든 자료, 판매 신청 상태
(판매 수익: Phase 3)
```

## 6. 기능 요구사항

### 6-1. 무료 학습자료

무료 회원과 비회원이 허들링의 공개 콘텐츠를 볼 수 있어야 합니다.

필수 기능:

1. 콘텐츠 목록 보기
2. 카테고리별 필터링
   - AI 실무
   - Figma + AI
   - 바이브코딩
   - 자동화
   - 콘텐츠 제작
   - 1인 사업가 운영
3. 무료/유료 표시
4. 유료 콘텐츠 미리보기
5. 앱 가입 또는 유료 전환 CTA

무료 콘텐츠는 전부 앱 안에만 가두지 않습니다. 공개 웹(`huddling.ai`)에서는 검색과 공유가 가능해야 하며, 앱에서는 이어서 학습·저장·미션 수행이 가능해야 합니다.

---

### 6-2. 유료 멤버 자료실

유료 회원은 강의자료, 다시보기, PDF, 워크북, 템플릿을 한곳에서 확인할 수 있어야 합니다.

필수 기능:

1. 자료 목록 보기
2. 강의/코호트/주제별 필터링
3. 파일 다운로드 또는 링크 열기
4. 멤버십 권한에 따른 접근 제한
5. 최근 본 자료/저장한 자료
6. 자료별 업데이트 날짜 표시

---

### 6-3. 스킬/프롬프트 라이브러리

하이서가 만든 검증된 프롬프트와 스킬 파일을 구조화된 카드 형태로 제공해야 합니다.

각 카드에는 최소한 다음 정보가 필요합니다.

```txt
스킬명:
카테고리:
난이도:
추천 대상:
사용 도구:
언제 쓰나요?:
준비물:
프롬프트 또는 파일:
사용 순서:
예시 결과:
주의할 점:
업데이트 날짜:
권한: 무료 / 유료 / 특정 코호트 전용
```

필수 기능:

1. 스킬 카드 목록
2. 검색
3. 태그 필터
4. 복사 버튼
5. 파일 다운로드
6. 예시 결과 보기
7. 난이도 표시
8. 관련 미션 연결

---

### 6-4. 미션과 학습 관리

유료 멤버는 매달 실무 적용 산출물을 만들고 제출할 수 있어야 합니다.

권장 월간 제출 구조:

```txt
월간 허들링 산출물
1. 내가 만든 AI 업무 자동화 자산 1개
2. 내가 실제 업무에 적용한 사례 1개
```

또는

```txt
월간 제출물
- 프롬프트 1개
- 스킬/템플릿 1개
- 사용 후기 1개
```

필수 기능:

1. 현재 미션 보기
2. 제출하기
3. 제출 상태 확인
   - 작성 중
   - 제출 완료
   - (피드백 대기 / 수정 요청 / 승인됨: 피드백 기능과 함께 다음 단계에서 추가)
4. ~~피드백 기록 보기~~ (MVP 제외 · 다음 단계)
5. 내 완료 미션 목록
6. 제출 완료된 제출물을 내 자산으로 전환하기

---

### 6-5. 내 자산

멤버는 자신이 만든 프롬프트, 스킬 파일, 자동화 템플릿, 사용 사례를 자산으로 저장할 수 있어야 합니다.

필수 기능:

1. 내 자산 목록
2. 새 자산 등록
3. 파일 첨부
4. 설명 작성
5. 공개 범위 선택
   - 비공개
   - 멤버 공개
   - 판매 신청 (판매 승인 회원만 선택 가능)
6. 판매 신청 상태 확인
   - 임시저장
   - 검수 대기
   - 수정 요청
   - 승인됨 (MVP 1차의 최종 상태)
   - 반려
   - 판매 중 (Phase 2)
   - 판매 중지 (Phase 2)
7. ~~판매 수익 확인~~ (Phase 3)

---

### 6-6. 허들링 픽 — 큐레이션형 멤버 자산 마켓 (MVP 제외 · Phase 2)

초기에는 완전한 오픈마켓이 아니라 **검수형 큐레이션 마켓**으로 운영합니다.

허들링 픽 정의:

> 멤버들이 직접 만들고, 허들링이 검수한 AI 실무 자산

필수 기능:

1. 판매 자산 목록
2. 미리보기
3. 가격 표시
4. 제작자 표시
5. 포함 내용 표시
6. 사용 조건 표시
7. 구매 또는 구매 예정 CTA
8. 구매한 자산 목록
9. 판매자 수익 내역

> **MVP 1차 제외 (Phase 2)**: 허들링 픽 섹션과 구매자 흐름은 이번 범위에 포함하지 않습니다. MVP 1차는 판매 신청 → 검수 → **승인됨**까지만 구현하며, `판매 중`·`판매 중지` 상태와 허들링 픽 노출은 Phase 2, 결제와 정산은 Phase 3에서 붙입니다.

---

### 6-7. 운영자 검수

운영자는 멤버가 제출한 판매 신청 자료를 검수할 수 있어야 합니다.

필수 기능:

1. 검수 대기 목록
2. 자산 상세 보기
3. 판매 기준 체크리스트 (검수 시 필수 사용)
4. 승인/수정 요청/반려
5. 수정 요청 코멘트 작성 (판매 검수 절차이며, 미션 피드백과는 별개)
6. ~~허들링 픽 선정~~ (Phase 2)
7. 가격 설정 또는 가격 승인
8. ~~판매 중지 처리~~ (Phase 2)
9. 판매 회원 수동 승인 (유료 회원 → 판매 승인 회원 역할 변경)

> MVP 1차에서는 검수를 운영자가 수동으로 진행합니다. 운영자 부담은 (1) 판매 신청 권한을 판매 승인 회원으로 제한하고 (2) 판매 기준 체크리스트를 필수로 사용해 하이서 외 운영진도 동일한 기준으로 검수할 수 있게 하는 방식으로 분산합니다. AI 1차 검수는 MVP 이후 단계에서 검토합니다.

판매 가능한 자료 기준:

1. 실제 업무에 써본 것
2. 결과 예시가 있는 것
3. 사용 방법이 명확한 것
4. 초보자가 따라할 수 있는 것
5. 특정 툴/버전/환경 조건이 적혀 있는 것
6. 개인정보/고객정보/회사기밀이 없는 것
7. 저작권 문제가 없는 것
8. 구매자가 바로 써볼 수 있는 것

## 14. 조건

- 앱은 최소 두 그룹, 즉 학습자/멤버와 운영자가 함께 쓰는 것을 전제로 설계합니다.
- Discord는 대화와 커뮤니티 온도감을 담당하고, 앱은 자료·학습·제출·피드백·자산화를 담당합니다.
- 멤버가 만든 자료는 기본적으로 비공개이며, 본인이 선택한 경우에만 멤버 공개 또는 판매 신청이 가능합니다.
- 판매 자산은 운영자 검수를 통과해야 합니다.
- 개인정보, 고객정보, 회사기밀, 타인의 저작물은 판매 자산에 포함될 수 없습니다.
- 필요한 이미지·아이콘·더미 텍스트는 직접 조달하되, 비주얼 톤과 디자인 규칙은 **`design.md`(디자인 시스템 문서)를 기준**으로 합니다. (모노크롬 캔버스 + 단일 액센트, 그림자 없는 깊이 표현, 필(pill) 형태 인터랙션 등 — 세부 규칙과 Do's and Don'ts는 `design.md` 참조)
- 최종적으로 보는 것은 보기 좋은 화면뿐 아니라 **AI 에이전트가 읽고 이어서 작업할 수 있는 데이터로서의 디자인**입니다.

## 15. 이렇게 평가해요

### 문제 해결의 완성도

무료 콘텐츠, 유료 자료, 하이서의 검증 자산, 멤버 제출물, 판매 가능 자산이 서로 다른 권한과 상태로 관리되는지를 봅니다. 단순히 자료를 나열하는 수준이라면 핵심 문제를 해결하지 못한 것입니다.

### 학습 흐름의 완성도

사용자가 콘텐츠를 보고 끝나는 것이 아니라, 미션을 수행하고, 제출하고, 피드백받고, 자신의 자산으로 남기는 흐름이 화면 구조로 드러나야 합니다.

### 자산화 구조의 완성도

멤버가 만든 산출물이 어떻게 비공개 자료에서 판매 신청 자료로 바뀌고, 검수를 거쳐 허들링 픽으로 선정되는지 명확해야 합니다.

### 디자인 완성도

AI 실무 학습자, 1인 사업가, 디자이너, 강사, 운영자가 모두 이해할 수 있는 직관적인 정보 구조가 필요합니다. 자료실처럼 보이기보다 실험실과 자산 라이브러리의 느낌이 살아야 합니다.

> 비주얼 표현은 `design.md` 기준을 따르며, 토큰·컴포넌트가 `design.md` 규칙을 위반하지 않았는지를 함께 봅니다.

### 운영 지속가능성

하이서가 모든 피드백과 검수를 직접 떠안지 않도록, 상태 관리·체크리스트·AI 1차 검수·운영자 권한 구조가 고려되어야 합니다.

> MVP 1차에서는 AI 1차 검수 없이 **판매 승인 회원 제한 + 필수 체크리스트 + 복수 운영자 권한**으로 부담을 분산합니다. AI 1차 검수는 MVP 이후 단계에서 검토합니다.

### 데이터 구조화

프롬프트, 스킬 파일, 미션, 제출물, 판매 자산이 AI 에이전트가 읽고 이어서 작업할 수 있는 구조로 설계되어야 합니다. 텍스트 덩어리나 이미지 중심의 디자인만으로는 부족합니다.
